# 特征和标签命名撞概念:return_5d 到底是过去还是未来?

## 坑长什么样

特征文件里有:

```python
# features/make_features.py
df['return_5d'] = df.groupby('ticker')['close'].pct_change(5)
```

标签文件里算的是"未来 5 日收益":

```python
# labels/make_labels.py
label = (close.shift(-6) / close.shift(-1) - 1)   # 未来 5 日
```

两个东西概念相反,但名字里都有 "return" + "5d"。

## 为什么是个坑

`pct_change(5)` 算的是 **(close_t / close_{t-5}) - 1**,也就是**过去 5 天**的累计收益 —— 这是一个**已知的历史信息**,可以当特征。

而标签是**未来 5 天**的收益 —— 这是要**预测的目标**。

两者都叫 `return_5d` 的话:
- 训练时一不小心把"未来收益"那一列当特征喂进模型 → **数据泄漏(look-ahead bias)**,
  模型在训练集上表现好得离谱,实盘直接失效
- code review 时看到 `return_5d` 根本分不清是哪个
- 这是量化里最经典、最致命的 bug 之一,且很隐蔽(不报错,只是结果是假的)

## 解决:命名上就把"过去"和"未来"分开

| 类型 | 命名 | 含义 | 时间方向 |
|---|---|---|---|
| 特征 | `mom_5d` | 过去 5 日动量 (t-5 → t) | 回看,已知 |
| 标签 | `label_5d` | 未来 5 日收益 (t+1 → t+6) | 前看,待预测 |

- 特征用 `mom_` (momentum) 前缀,绝不用 `return_`
- 标签统一加 `label_` 前缀
- 一看前缀就知道这列能不能进模型

## 教训

1. **命名是防数据泄漏的第一道防线**。`return` 这个词太含糊,在特征里禁用。
2. 特征 = 只能用 t 时刻及以前的信息;标签 = t 之后的信息。前缀上就要体现这个区别。
3. 训练前加一道检查:特征列名里不允许出现 `label`、`future`、`fwd` 等前看词。
4. 同样一个 `pct_change`,正负号、shift 方向不同,意义就完全相反 —— 写的时候在注释里写清楚时间区间,例如 `# (t-5 → t)`。
