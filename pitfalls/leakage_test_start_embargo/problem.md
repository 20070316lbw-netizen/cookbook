# 隔离带与数据泄露：验证集和测试集不要硬切割

## 坑长什么样

在时序量化模型中，如果 `label` 是未来 5 天的收益，在切分数据集时直接在日历上硬切：
```python
train_df = df[df["date"] <= "2023-12-31"]
test_df  = df[df["date"] >= "2024-01-01"] # ❌ 紧挨着 train
```

## 为什么会炸

因为在 `2023-12-31` 这一天的训练样本里，它的 `label` 用到了未来 5 个交易日（比如 `2024-01-02` 到 `2024-01-08`）的价格数据。
但同时，`2024-01-02` 已经在测试集 `test_df` 里了！这就导致了**未来数据泄露**（Lookahead Bias）。模型在训练时“偷看”到了测试集期间的价格走势。

## 怎么解

在时间序列中，训练集和测试集/验证集之间，必须加入**隔离带（Embargo）**。隔离带的长度必须 **≥ 标签向前看的交易日天数**。

更重要的是：**不要用日历日，要用真实的交易日来计算隔离带**。因为周末和节假日是不交易的，日历日推迟 7 天可能只包含 4 个交易日，依然无法彻底防止泄露。

```python
# ✅ 正确写法：获取实际的交易日列表，按天数顺延
trading_days = sorted(df["date"].unique())
idx = trading_days.index(train_end_date)
# 往后延 embargo_days (例如标签用未来5日收益，这里就至少设为 6)
test_start_date = trading_days[idx + embargo_days]

test_df = df[df["date"] >= test_start_date]
```

## 教训

凡是切分时间序列数据集，首要问题是问自己：“我的标签最多向前看了几天？”。然后必须在所有切分点加入对应的交易日隔离带。把计算 `test.start` 的逻辑交给代码基于 `train.end` 动态算出来，而不是写死在配置文件里。
